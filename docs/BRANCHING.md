# 브랜치 룰 (Branching Rules)

> 또맛또(TMT) 백엔드 레포의 브랜치 전략·네이밍·머지 규칙. (TMT-55)
> 이 문서의 확정 = 본 PR에 BE 팀원 approve. 변경은 PR로만.

## 1. 전략: GitHub Flow

`main` + 작업 브랜치, 두 종류만 쓴다. **develop / release 브랜치 없음.**

```
main ←── PR (squash merge) ←── feat/TMT-50
```

- `main`은 항상 배포 가능한 상태를 유지한다
- `main` 직접 push 금지 — PR + **최소 1명 approve** + CI 통과 후 머지
- 배포는 `main` 기준 (태그/릴리즈는 배포 파이프라인 확정 시 추가)

### 왜 git-flow가 아닌가

BE 3명·배포 환경 1개인 사이드 프로젝트에서 develop/release/hotfix 브랜치는 관리 비용만 추가된다. 도그푸딩 단계에는 GitHub Flow로 충분하며, 스테이징 환경이 생기면 그때 재논의한다.

## 2. 브랜치 네이밍

```
<type>/<Jira키>
```

| type | 용도 | 예시 |
|---|---|---|
| `feat` | 기능 추가 | `feat/TMT-50` |
| `fix` | 버그 수정 | `fix/TMT-100` |
| `refactor` | 동작 변경 없는 개선 | `refactor/TMT-150` |
| `docs` | 문서 | `docs/TMT-55` |
| `chore` | 빌드·설정·의존성 | `chore/TMT-160` |
| `test` | 테스트만 | `test/TMT-165` |

- **Jira 키 필수** — 이슈 없이 브랜치 없음 (긴급 수정은 사후 이슈 발급 허용)
- 브랜치의 작업 내용은 Jira 이슈 제목이 말해준다 (별도 설명 suffix 없음)
- 브랜치 수명은 최대 1주를 넘기지 않는다. 길어지면 이슈를 쪼갠 신호

## 3. 커밋 컨벤션

[Conventional Commits](https://www.conventionalcommits.org/ko/) — `type: 제목` (본문 한국어 OK)

```
feat: 그룹 가입 API 추가 (TMT-50)
fix: 리뷰 3개 미만 조회 시 NPE 수정
```

- 제목 50자 내, 명령형
- squash merge라서 **브랜치 내 중간 커밋은 자유** — PR 제목이 곧 main의 커밋 메시지가 되므로 PR 제목만 규칙을 지키면 된다

## 4. PR · 머지 규칙

### PR 생성 전 — 셀프 리뷰 의무

**자신이 만든 코드는 PR 올리기 전에 본인이 전부 검토한다.** AI가 생성한 코드도 예외 없음 — 읽고 이해하지 못한 코드를 올리는 것은 리뷰 부담을 팀원에게 전가하는 안티패턴이다 (팀 그라운드 룰 ⑥).

- [ ] diff를 처음부터 끝까지 직접 읽었다
- [ ] 로컬에서 빌드·테스트를 통과했다
- [ ] 리뷰어가 15분 안에 읽을 수 있는 크기다

### PR 크기 가이드

**변경 ±300줄 권장.** 넘어가면 이슈/PR 분할을 먼저 고민한다. 48시간 리뷰 룰이 돌아가려면 PR이 부담 없이 읽히는 크기여야 한다. (생성 코드·마이그레이션 등 기계적 변경은 예외 — PR 본문에 명시)

### 리뷰 코멘트 등급

리뷰 코멘트에는 등급을 붙인다. 등급 없는 코멘트는 `[want]` 취급.

| 등급 | 의미 |
|---|---|
| `[must]` | 머지 전 반드시 반영 |
| `[want]` | 권장 — 반영 여부는 작성자 판단 |
| `[q]` | 질문 — 답변만 하면 됨 |

### 머지 조건

| 항목 | 규칙 |
|---|---|
| 방식 | **Squash merge** — main 히스토리 = PR 단위 |
| PR 제목 | `[TMT-50] 그룹 가입 API` (squash 커밋 메시지로 사용됨) |
| 조건 | **최소 1명 approve** + CI(빌드·테스트) 통과 |
| 리뷰 부재 시 | **리뷰 요청 후 48시간 내 리뷰가 없으면 머지 가능** (CI 통과 전제, 사후 리뷰 환영) |
| 머지 후 | 작업 브랜치 삭제 (자동 삭제 설정) |

## 5. Jira 상태 전환 (본인이 직접)

```
브랜치 생성 → In Progress  /  PR 오픈 → In Review  /  머지 → Done
```

## 6. 시크릿 커밋 금지

- `.env`, 키 파일, 토큰 등 시크릿은 **절대 커밋하지 않는다** — `.gitignore`에 선등록
- 실수로 커밋했다면 히스토리에서 지우는 것으로 끝내지 말고 **해당 시크릿을 즉시 rotate** (한 번 push된 시크릿은 유출로 간주)
- 설정값은 환경 변수 또는 별도 vault로 주입
